## 一、开发总览

### 1.1 项目目标

构建「广东精酿啤酒一站式供应链」微信小程序，包含 C 端（客户端）完整功能和 B 端（供应商管理后台），采用 UniApp + Supabase 全栈方案，7 周内完成开发并提交微信审核。

### 1.2 技术栈

| 层级 | 技术选型 | 版本 |
|------|---------|------|
| 前端框架 | UniApp（Vue3 Composition API） | 3.x |
| 开发语言 | TypeScript | 5.x |
| 状态管理 | Pinia | 2.x |
| UI 组件库 | uni-ui | 最新版 |
| 样式 | SCSS | — |
| 后端即服务 | Supabase（PostgreSQL + Storage + Auth + RLS） | — |
| 微信能力 | 微信原生 API | — |
| 地图 | 腾讯地图（小程序 map 组件） | — |

### 1.3 本期明确不实现

| 功能 | 原因 |
|------|------|
| 微信支付（wx.requestPayment） | 价格面议，线下/转账结算 |
| 后台改价 / 成交价确认 | 本期不做 |
| 配送当日提醒订阅消息 | 无配送日历数据源 |
| 配送日历 | 本期无配送排期数据 |
| 优惠活动业务逻辑 | 二期实现 |
| 数据报表多维分析 | 二期实现 |
| 小程序码渠道统计 | Could，M4 有余量再做 |

## 三、数据库设计

### 3.1 建表 DDL（001_init.sql）

```sql
-- 启用 UUID 扩展
CREATE EXTENSION IF NOT EXISTS "pgcrypto";

-- 用户表
CREATE TABLE users ( ... );

-- 产品分类表
CREATE TABLE categories ( ... );

-- 产品表
CREATE TABLE products ( ... );

-- 客户意向表
CREATE TABLE customers ( ... );

-- 报修工单表
CREATE TABLE repair_orders ( ... );

-- 合作方案表
CREATE TABLE plans ( ... );
```

详见 `developer.md` 第五节完整 DDL。

### 3.2 RLS 策略

| 表 | 普通用户权限 | Admin 权限 |
|---|------------|-----------|
| products | SELECT（is_active=true） | ALL |
| customers | SELECT/INSERT（自己的记录） | ALL |
| repair_orders | SELECT/INSERT（自己的记录） | ALL |

### 3.3 Supabase Storage Bucket

| Bucket | 用途 | 权限 |
|--------|------|------|
| products | 产品主图 + 详情图 | 公开读，认证用户写 |
| repairs | 报修故障照片 | 私有读（仅本人），认证用户写 |

## 五、接口清单

### 5.1 C 端接口

| 接口 | 方法 | Supabase 操作 | 备注 |
|------|------|--------------|------|
| 获取产品列表 | GET | `products.select` | 支持分类筛选、关键词搜索 |
| 获取产品详情 | GET | `products.select.eq('id')` | — |
| 获取合作方案 | GET | `plans.select` | — |
| 提交预约 | POST | `customers.insert` | 需登录（user_id） |
| 查询我的预约 | GET | `customers.select.eq('user_id')` | — |
| 提交报修工单 | POST | `repair_orders.insert` | 含图片 URL 数组 |
| 查询我的工单 | GET | `repair_orders.select.eq('user_id')` | — |
| 图片上传 | PUT | Supabase Storage | wx.chooseMedia → Storage |
| 微信登录 | POST | Edge Function: wx-login | code → openid → JWT |

### 5.2 B 端接口

| 接口 | 方法 | Supabase 操作 | 备注 |
|------|------|--------------|------|
| 获取所有产品 | GET | `products.select`（无 is_active 过滤） | Admin only |
| 新增产品 | POST | `products.insert` | — |
| 编辑产品 | PATCH | `products.update.eq('id')` | — |
| 上/下架产品 | PATCH | `products.update.eq('id')` | `is_active` 字段 |
| 获取客户列表 | GET | `customers.select`（支持 status 筛选） | Admin only |
| 获取客户详情 | GET | `customers.select.eq('id')` | — |
| 更新客户跟进状态 | PATCH | `customers.update.eq('id')` | status + follow_note |
| 获取工单列表 | GET | `repair_orders.select`（支持 status 筛选） | Admin only |
| 更新工单状态 | PATCH | `repair_orders.update.eq('id')` | status + assignee + handler_notes |
| 看板统计 | GET | `customers.select`（今日，count） | 前端聚合 |

| 微信小程序审核被拒（酒类资质） | 中 | 高 | 提前准备食品经营许可证/酒类零售许可证，选好类目 |
| Supabase Edge Function wx-login 延迟高 | 低 | 中 | 备选方案：前端直接用 openid+自定义密码登录，Edge Function 仅用于 code→openid 换取 |
| 腾讯地图 API Key 额度超限 | 低 | 低 | 地图仅用于配送区域展示和定位，免费额度充足 |
| 微信订阅消息模板申请被拒 | 中 | 低 | M2–M3 阶段不依赖订阅消息，站内 Toast 替代，M4 再申请 |
| 图片上传速度慢（Supabase Storage 海外节点） | 中 | 中 | 图片压缩后上传（限 500KB 以内），显示上传进度 |
| 包体积超 2MB | 低 | 中 | 提前配置分包加载（admin 后台独立分包） |

## 十、开发流程规范

### 10.1 分支策略

```
main          ← 生产分支，只接受来自 release 的合并
  └── release ← 发布分支，Sprint 结束合并
        ├── feature/S1-框架搭建
        ├── feature/S2-首页产品
        ├── feature/S3-C端功能
        ├── feature/S4-B端后台
        └── feature/S5-微信能力
```

### 10.2 代码规范

- 所有异步操作使用 `async/await` + `try/catch`
- 组件命名：PascalCase（`ProductCard.vue`）
- 工具函数命名：camelCase（`formatPrice.ts`）
- 页面内不直接调用 Supabase，通过 composables 封装
- 敏感信息只存 `.env`，不硬编码
