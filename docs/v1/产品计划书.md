## 一、项目背景与目标

### 1.1 业务背景

本项目为**精酿啤酒一站式供应链**打造专属微信小程序，核心客户群体为：

- 宵夜档／夜市地摊
- 大排档／路边摊
- 小型餐饮档口

主营业务包括：

| 业务类型 | 说明 |
|---------|------|
| 桶装鲜啤配送 | 按需定期送货上门（珠三角当日达，其他地区走物流） |
| 设备提供 | 打酒机、啤酒车；支持**出售**或**租赁**两种方式，客户按需选择 |

### 1.2 为什么选择微信小程序

| 对比维度 | 网页版 | 微信小程序 |
|---------|--------|-----------|
| 触达方式 | 需要用户主动搜索/记住网址 | 微信内扫码、搜索、好友分享即可打开 |
| 用户门槛 | 需注册账号才能使用 | **无需注册/登录即可浏览全部内容** |
| 分享获客 | 分享链接体验差 | 分享卡片，好友点击直接进入 |
| 消息触达 | 无法主动推送 | 订阅消息（如新意向提醒等） |
| 目标用户适配 | 需记住网址，门槛略高 | 档口老板日常用微信，使用习惯完全匹配 |
| 支付能力 | 需额外接入 | 本期**不接入**在线支付；价格面议，线下/转账结算 |
| 地理位置 | 需用户授权 | 微信授权后精准获取，用于档口定位填写 |

> **核心结论**：目标客户（宵夜档/大排档老板）的主要数字工具就是微信，小程序比网页更贴近他们的使用场景，获客成本更低，转化率更高。

### 1.3 建设目标

1. **品牌曝光**：微信生态内裂变传播，让更多档口主动找到我们
2. **零门槛体验**：打开即用，无需注册登录，任何人均可浏览产品与方案
3. **线上获客**：轻量表单提交合作意向，只需昵称+电话，降低填写门槛
4. **方案展示**：清晰呈现合作套餐，降低客户决策门槛
5. **产品自管理**：供应商通过小程序后台随时上下架产品，无需技术人员介入

### 1.4 一期范围与验收边界（与 MoSCoW 对齐）

| 主题 | 一期（M2–M3 必验收） | M4（Should） | 二期 / Could（不纳入一期验收） |
|------|---------------------|----------------|--------------------------------|
| **B 端产品管理** | 产品列表 + 新增/编辑 + 上架/下架 + 排序 | — | 批量操作、标签管理 |
| **B 端入口** | 管理员 openid 提前写入库；登录后「我的」显示后台入口 | — | 独立管理 App |
| **订阅消息** | **不强制**：意向提交以 Toast + 站内「我的」列表刷新为准 | 接入「新意向→供应商」模板并验收 | 其他通知类 |
| **优惠活动** | **不做**：无发券、无「我的优惠券」业务逻辑 | — | 活动页、优惠券、优惠类订阅消息 |
| **小程序码** | **默认不做** | 可选加菜：带 `source` 写库 | 全渠道统计看板 |
| **合作方案 `plans`** | 前台读种子数据；**一期无**「后台方案编辑」页 | — | 运营后台可视化改方案 |

### 3.6 在线咨询

> 核心能力：微信客服组件（`open-type="contact"`）。用户点击后在微信内直接与供应商展开对话，**无需跳出小程序、无需复制微信号**，是最低摩擦的沟通路径。

#### 入口分布（全局覆盖）

| 页面 | 入口形式 |
|------|---------|
| 首页 | 底部悬浮按钮点击 → 弹出咨询 ActionSheet |
| 产品详情页 | 底部固定栏「一键咨询」按钮直接触发 |
| 合作方案页 | 方案卡片底部「咨询详情」按钮 |
| 我的 | 「联系我们」区域展示全部联系方式 |

#### 咨询方式 ActionSheet（半屏弹层）

```
┌─────────────────────────┐
│                         │
│  ┌───────────────────┐  │
│  │   联系供应商       │  │
│  ├───────────────────┤  │
│  │  💬 微信在线咨询   │  │  ← open-type="contact"
│  ├───────────────────┤  │
│  │  📞 拨打电话       │  │  ← wx.makePhoneCall
│  ├───────────────────┤  │
│  │  📋 复制微信号     │  │  ← wx.setClipboardData
│  ├───────────────────┤  │
│  │     取消          │  │
│  └───────────────────┘  │
└─────────────────────────┘
```

#### 微信客服配置

| 配置项 | 说明 |
|--------|------|
| 开通条件 | 在微信公众平台 → 功能 → 微信客服中绑定客服微信号（支持个人微信） |
| 组件用法 | `<button open-type="contact" session-from="页面标识">在线咨询</button>` |
| session-from | 传入页面来源（如 `product_detail`、`homepage`），方便客服识别用户场景 |
| 客服响应 | 在微信「微信客服」App 内回复，消息推送至用户微信通知 |
| 离线处理 | 客服离线时用户可留言，客服上线后回复 |

**UniApp 代码示例：**

```html
<button
  open-type="contact"
  session-from="product_detail"
  :show-message-card="true"
  send-message-title="我想咨询这款产品"
  :send-message-path="`/pages/products/detail?id=${productId}`"
  :send-message-img="product.cover_image"
>
  💬 在线咨询
</button>
```

## 五、微信生态能力集成

### 5.1 用户登录与管理员鉴权

**登录流程（「我的」主动触发）：**

```
用户进入「我的」页面
    ↓
【未登录】显示「点击登录」引导卡片
    ↓
用户主动点击 → wx.getUserProfile() 获取昵称/头像
              + wx.login() 获取 code → 云函数换取 openid
    ↓
openid 写入云数据库 users 集合（首次登录时新建记录）
    ↓
查询 users 集合中该 openid 的 role 字段
    ↓
role === 'admin' → 显示「供应商后台」入口（管理员 openid 已提前写入库）
role === 'customer' 或无记录 → 普通用户界面，显示意向记录
```

**管理员开通方式：**

```
运营人员（不需要技术人员）直接在云开发控制台：
1. 打开云开发控制台 → 数据库 → users 集合
2. 新增一条记录：
   { openid: "管理员微信openid", role: "admin", nickname: "小王" }
3. 保存后，该微信账号登录小程序即可看到后台入口
```

## 六、技术架构

### 6.1 技术选型

| 层级 | 选择 | 说明 |
|------|------|------|
| 开发框架 | **UniApp** | 一套代码同时发布小程序 + H5，基于 Vue3 |

| 状态管理 | Pinia | 管理用户信息、产品缓存等全局状态 |
| 云服务 | **腾讯云开发（CloudBase）** | 数据库 + 云存储 + 云函数，微信生态原生支持 |
| 图片存储 | **微信云存储**（`wx.cloud.uploadFile`） | 与小程序原生打通，fileID 直接存库 |
| 地图/位置 | 微信原生 `wx.getLocation` | 获取坐标，无需额外地图 SDK |
| 微信能力 | 微信原生 API | wx.login / wx.getUserProfile / 订阅消息等 |

### 6.2 数据流设计

```
小程序前端（C端 / 游客）
├── GET  products     → 云数据库（读取上架产品，无需登录）
├── GET  plans        → 云数据库（读取合作方案，无需登录）
└── POST customers    → 云数据库（提交意向，无需登录；已登录时附带 openid）

小程序前端（已登录普通用户）
└── GET  customers    → 云数据库（按 openid 查询自己的意向记录）

供应商后台（管理员）
├── CRUD products     → 云数据库（产品增删改查）
├── PATCH is_active   → 云数据库（上架/下架）
└── wx.cloud.uploadFile → 云存储（上传产品图片，返回 fileID）
```

### 6.3 鉴权方案

```
游客（未登录）：
页面直接渲染，无鉴权拦截
产品、方案、意向表单均可正常访问和提交

普通用户（已登录）：
wx.login() → openid → 查询 users 集合
role = 'customer' → 可查看自己的意向记录

管理员（已登录）：
wx.login() → openid → 查询 users 集合
role = 'admin'（提前写入）→ 显示后台入口
访问 /admin/* 页面时服务端再次校验 role，非 admin 跳回首页
```

## 八、UI 设计规范

### 8.1 视觉风格

- **主色调**：琥珀金 `#F5A623`、深棕 `#3E1C00`、乳白 `#FFF8F0`
- **辅助色**：橙红 `#E84C3D`（活动标签、紧急提示）
- **背景色**：`#F7F3EE`（米白，接地气）
- **字体**：系统字体（PingFang SC / 微软雅黑）

### 8.2 关键组件规范

| 组件 | 规范 |
|------|------|
| 主按钮 | 琥珀金底色，圆角 8px，高 44px |
| 次级按钮 | 白底 + 琥珀金描边 |
| 产品卡片 | 圆角 12px，白底，轻阴影 |
| 标签/Tag | 热销=橙红，新品=绿色，圆角 4px |
| 表单输入框 | 下划线风格，轻量感 |
| 必填标记 | 红色星号 `*` 置于字段名右侧 |
| 选填标记 | 字段名后灰色文字「（选填）」 |

### 8.3 移动端体验原则

1. **打开即用**：首页、产品、方案无任何登录拦截，确保第一印象流畅
2. **点击区域最小 44px**：确保手指可准确点击所有交互元素
3. **核心操作不超过 3 步**：从首页到完成意向提交，最多 3 次点击
4. **加载状态友好**：图片懒加载 + 骨架屏（Skeleton Screen）
5. **空状态设计**：产品列表为空时展示引导文案，不显示空白页
6. **底部安全区适配**：兼容 iPhone 底部 Home Indicator

### 8.4 交互与文案规范

| 规范项 | 要求 |
|--------|------|
| 空状态 | 所有列表页无数据时展示图标+引导文案，禁止空白页 |
| 加载状态 | 网络请求期间展示骨架屏，禁止无反馈白屏 |
| 错误处理 | 网络失败显示"加载失败，点击重试"，禁止崩溃 |
| 表单校验 | 仅对必填项（昵称+电话）校验，错误红字提示在字段下方 |
| 操作反馈 | 提交/保存成功后显示 Toast（持续2秒） |
| 危险操作 | 下架/删除前显示确认弹窗 |

**文案规范：**
- 按钮：动词开头（提交、预约、上架、保存）
- 错误提示：用"请"开头（请填写昵称、请输入正确的手机号）
- 成功提示：用"已"开头（已提交、已上架、已保存）
- 价格：无确定价格时显示"面议"，不显示"0"或空白
